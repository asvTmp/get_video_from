Техническое задание: PowerShell-скрипт для скачивания HLS-видео (.m3u8)

1. Общее назначение

Создать модульный консольный скрипт на PowerShell (get_video.ps1) для скачивания потокового видео (формат .m3u8) с помощью утилиты yt-dlp и склейки потоков через ffmpeg. Скрипт должен поддерживать два независимых сценария работы: одиночное скачивание по прямой ссылке и пакетное скачивание списка видео из JSON-файла.

2. Требования к окружению и структуре директорий

• Кодировка исходного кода: скрипт должен быть написан исключительно на чистом ASCII (английский язык для комментариев, строковых литералов и вывода в консоль), чтобы исключить ошибки парсинга в Windows PowerShell при сохранении в UTF-8 без BOM.
• Файловая структура проекта (относительно $PSScriptRoot):
	• get_video.ps1 — основной исполняемый скрипт.
	• .\bin\ — подпапка с внешними бинарными зависимостями: yt-dlp.exe, ffmpeg.exe, ffprobe.exe и сопутствующими .dll-библиотеками.
	• .\result\ — целевая директория по умолчанию для сохранения скачанных видеофайлов.

3. Параметры командной строки

Скрипт должен принимать следующие аргументы:
• -n, -Name [string] — имя выходного видеофайла (без расширения .mp4).
• -u, -Url [string] — прямая ссылка на .m3u8 плейлист.
• -f, -File [string] — путь к JSON-файлу со списком видео.
• -d, -dir_dst [string] — директория для сохранения видео. Значение по умолчанию: result (внутри $PSScriptRoot).
• -h, -Help, -? [switch] — вывод справки и завершение работы.

4. Логика валидации аргументов и справка (Show-Help, Start-Downloader)

• Автоматический вызов справки: если скрипт запущен без основных параметров (-n/-u или -f), с флагом -h/-Help, либо с некорректными/неизвестными аргументами ($args.Count -gt 0), скрипт должен вывести блок справки и завершить работу.
• Проверка конфликтов и полноты:
	• Запретить одновременную передачу -f и параметров одиночного режима (-n или -u).
	• В одиночном режиме требовать обязательное наличие обоих параметров (-n и -u).
• Содержание блока Show-Help:
	• Примеры вызова для одиночного и пакетного режимов.
	• Описание всех ключей и структуры папок (.\bin\, .\result\).
	• Наглядный пример валидного JSON-файла в кодировке UTF-8 со структурой массива объектов [{"name": "...", "url": "https://.../playlist.m3u8"}].

5. Архитектура и функциональные модули

Код должен быть разбит на изолированные функции с единой зоной ответственности:
1. Show-Help — форматированный вывод инструкции по использованию и шаблона JSON.
2. Get-SafeFileName — очистка имени файла: удаление дублирующегося расширения .mp4 в конце и замена запрещенных в файловой системе Windows символов (\ / : * ? " < > |) на символ подчеркивания _.
3. Resolve-DestinationDir — разрешение пути назначения. Если передан относительный путь, он привязывается к $PSScriptRoot. Если целевая папка (включая вложенные) отсутствует, она создается автоматически (New-Item -ItemType Directory -Force).
4. Invoke-VideoDownload — скачивание одного ролика:
	• Проверка наличия .\bin\yt-dlp.exe.
	• Проверка существования итогового .mp4 файла. Если файл уже существует и его размер больше 0 байт (Length -gt 0), скачивание пропускается с выводом статуса [Skipped].
	• Вызов yt-dlp.exe с параметрами:
		• --ffmpeg-location <путь_к_bin> (чтобы гарантированно подхватывались ffmpeg.exe и ffprobe.exe из папки bin).
		• --no-overwrites и --windows-filenames.
		• Без устаревшего флага -f "best" (использовать выбор лучшего качества по умолчанию во избежание WARNING в stderr).
5. Invoke-BatchDownload — пакетная обработка JSON:
	• Чтение файла в кодировке UTF-8 (Get-Content -Raw -Encoding UTF8 | ConvertFrom-Json) с обработкой ошибок синтаксиса через try/catch.
	• Отображение прогресса по элементам (Item X of Y), валидация наличия полей name и url у каждого объекта и последовательный вызов Invoke-VideoDownload.
6. Start-Downloader — точка входа, валидация параметров и маршрутизация выполнения между одиночным и пакетным режимами.
